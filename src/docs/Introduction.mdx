# Solutions Design System

A React component library built on **Mantine v9**, generated from the Figma library
**"Solutions Library- 2026"** (file key `KihJKyGA20stc2SSjAlxYU`).

Every colour, type scale, spacing step and radius is read out of that Figma file's variables — for
both light and dark mode — so design and code share one source of truth rather than drifting apart.

## How this library is put together

The design system is **mostly a Mantine theme**. Rather than wrapping every primitive, the Figma
styling is configured centrally in `src/theme/components.ts` and the underlying Mantine components
are re-exported. That means:

- A treatment is defined **once** and reached through a `variant` prop — `<Card variant="glass">`,
  `<Button variant="outline">` — instead of being repeated at call sites.
- Components take **Mantine's own props** (`variant`, `size`, `radius`, `color`, `disabled`, …), so
  the Mantine documentation applies directly.
- Only components with structure of their own are wrapped: `Card`, `IconCard`, `Form`, `Search`
  and `TableOfContents`.

## Install

```bash
pnpm add solutions-design-system @mantine/core @mantine/hooks
```

`@mantine/core`, `@mantine/hooks`, `react` and `react-dom` are peer dependencies. Mantine v9
requires React 19.2 or newer.

## Use

Wrap your app in `SolutionsProvider` once — it applies the theme and publishes the `--sds-*`
variables that the components rely on.

```tsx
import '@mantine/core/styles.css'
import { SolutionsProvider, Button, Card, TextInput } from 'solutions-design-system'

function App() {
  return (
    <SolutionsProvider defaultColorScheme="dark">
      <Card title="Get started" description="Everything is themed from Figma.">
        <TextInput label="Work email" placeholder="you@company.com" />
        <Button>Continue</Button>
      </Card>
    </SolutionsProvider>
  )
}
```

Dark is the library's native mode in Figma, so it is the default; pass
`defaultColorScheme="light"` or `"auto"` to change that.

## What's in here

- **Overview → Design Tokens** — every token, in both modes, with the Figma name it came from.
- **Components** — each component with a props table and live controls. Use the **Playground**
  story to experiment, and the **Color scheme** toolbar control to check both modes.

## Moving from the pre-Mantine version

The library previously shipped hand-rolled Tailwind components. Those have been replaced by themed
Mantine primitives:

| Before | Now |
| --- | --- |
| `Input` | `TextInput` |
| `Tag` | `Badge` |
| `Label` | `Chip` |
| `Button`, `Checkbox`, `Radio`, `Tabs`, `Accordion`, `Pagination`, `Badge` | same names, now Mantine's components with Mantine props |
| `Card`, `IconCard`, `Form`, `Search`, `TableOfContents` | unchanged names, rebuilt on Mantine |

Prop shapes follow Mantine rather than the previous bespoke APIs — for example
`<Button color="primary" variant="solid">` becomes `<Button variant="filled">`, and the
list-driven `Tabs tabs={[…]}` / `Accordion items={[…]}` APIs are now Mantine's compound
`Tabs.Tab` / `Accordion.Item` children.

## Components with open design questions

A few components were originally generated from an ambiguous or mismatched Figma node and are
still worth confirming against the source file:

- **Search** — no standalone Search input was reachable via the API; built from the search icon
  plus the standard input chrome.
- **IconCard** — only the vertical/desktop variant was available to inspect; the horizontal layout
  is inferred rather than traced.
- **Pagination** — no assembled pagination bar existed at the given node.
